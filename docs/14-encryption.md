# Encryption

HEXA provides authenticated encryption both through the CLI (`hexa encrypt` /
`hexa decrypt`) and through library functions in `.he` programs. This document
covers how encryption works and how to use it.

## Algorithms

Two authenticated ciphers are implemented:

- **AES-256-GCM** — a standard, widely-deployed authenticated cipher.
- **ChaCha20-Poly1305** — a fast, well-studied authenticated stream cipher.

Both are AEAD ciphers: they provide **confidentiality** (the data is secret)
and **authenticity** (any tampering or a wrong key is detected). If the
authentication tag does not validate, decryption *fails* — it never silently
returns corrupted plaintext.

## Library API

```he
let k: key = crypto.key.generate(256);

let ct: ciphertext = crypto.encrypt.aes256_gcm(plaintext, k);
let pt: plaintext  = crypto.decrypt.aes256_gcm(ct, k);

let ct2: ciphertext = crypto.encrypt.chacha20_poly1305(plaintext, k);
let pt2: plaintext  = crypto.decrypt.chacha20_poly1305(ct2, k);
```

The types keep honest boundaries: you pass `plaintext`/`key` in and receive
`ciphertext` out; you cannot mix them up without the compiler noticing.

## CLI — the one-time key flow

The simplest, safest way to encrypt a file is the CLI:

```bash
hexa encrypt secret.txt
```

HEXA generates a fresh key, shows it **once** with a warning banner, and never
stores it:

```
============================================
  SINGLE-USE ENCRYPTION KEY — COPY IT NOW
============================================

  HX-9f3c1a57b0d24e68c1a5f02d9b3e77c4a6d8b1e0f392a5c7d4e1b0a3c5f7d9e2b

============================================
secret.txt.hexa written (AES-256-GCM, Argon2id-derived master key).
```

To decrypt:

```bash
hexa decrypt secret.txt.hexa
# prompt: paste the key (never echoed)
```

The decrypted file is written with the original content; a wrong or tampered
key fails the AEAD check with an error rather than corrupt output.

## What the CLI actually does

For `hexa encrypt file`:

1. Generate a random `HX-<hex>` key.
2. Optionally derive a master key from the one-time key with Argon2id
   (parameters recorded in the `.hexa` header).
3. Encrypt the file payload with AES-256-GCM or ChaCha20-Poly1305 using the
   `plaintext`.
4. Pack everything — magic, version, flags, algorithm, KDF + params, salt,
   nonce, metadata, payload, AEAD auth tag — into the `.hexa` v1 container.
5. Display the key once, wipe the in-memory copy, return.

See [HEXA-FORMAT.md](HEXA-FORMAT.md) for the exact byte layout.

## Multi-layer encryption

`crypto.encrypt.layers(data, layers)` and the corresponding CLI flow encrypt
the data **multiple times** with independently derived per-layer keys and nonces
from an HKDF key hierarchy. See
[Multi-layer encryption](15-multi-layer-encryption.md).

## Security notes

- The encryption key is generated by you/HEXA; keep it safe, because HEXA cannot
  recover it (see [Keys](12-keys.md)).
- Encryption protects against *reading* the data and *tampering* with it, given
  an uncompromised machine. It does not defend against a keylogger, screen
  capture of the one-time key display, or an already-compromised OS. See
  [Threat model](27-threat-model.md).
