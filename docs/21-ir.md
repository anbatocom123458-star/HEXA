# Intermediate representation (IR)

This document describes HEXA's intermediate representation plans. The current
milestone compiles **directly from the typed AST to assembly**, so a full
standalone IR is **(planned / later phase)**. This page documents the design so
readers understand where the compiler is going.

## Current state

In the current milestone, the compiler emits `x86_64` assembly straight from the
type-checked AST. This is simple and auditable — ideal for a bootstrap — but it
means optimizations and front-end/back-end separation are limited.

## Why an IR (planned)

A dedicated IR gives the compiler:

- A clean seam between the front end (lexer/parser/type checker) and back end
  (codegen).
- A place to run **optimizations** (constant folding, dead-code elimination,
  register allocation) independent of source details.
- A target for alternative back ends (other architectures, an interpreter/JIT)
  without re-writing the front end.
- Easier **debugging** and verification of generated code.

## Planned IR design

Planned properties:

- A **low-level, platform-independent** instruction set (similar in spirit to
  a typed SSA/three-address form).
- **Typed** so secret-safety information can flow into codegen (which values
  must be wiped, which must never be spilled to disk).
- **SPANS preserved** so diagnostics and debugging map back to source lines.

Each IR instruction would carry:

- an operation (load, store, add, call, branch, etc.),
- typed operands,
- a source span for debugging.

## Pipeline with IR (planned)

```
AST ──► typed AST ──► IR (optimized) ──► assembly ──► native
```

Because the IR would carry type and span information, the secret-safety rules
could be re-verified at the IR level, and codegen could ensure secrets are wiped
on every path.

## Relationship to disassembly/decompilation

The `hexa disassemble` and `hexa decompile` commands operate on compiled output.
A richer IR would make decompilation more faithful (see
[Decompilation](25-decompilation.md)), because much semantic structure lost in
assembly can be preserved in IR.

## Status

The IR is **design-only** for this milestone; the concrete AST→assembly path is
what ships today. Implementing the IR is a documented later phase.
